# 开始使用（v1.2，含 mancode 适配）

这是一套可携带的开发约定：明确交互逻辑，确认视觉依据与本次变更，再实现和检查真实 UI。已有系统默认沿用；新体系或明确的新方向请求才探索。目录保留完整八个文件，通过 README 与 AGENTS.md 非托管区域提供入口，并纳入 npm 打包清单；不自动安装到全局工具或其他项目。

## 已有 mancode 任务

把整个 develop-with-visual-spec 文件夹交给助手，可以这样说：

> 请在现有 mancode 流程上使用这份 v1.2 视觉约定，先读 MANCODE.md 与 SPEC.md，沿原 TaskRef、policy、绑定计划和账本继续。检查现有设计系统和我这次要求，明确 G2 的视觉依据与变更边界。同体系接续、新页面/布局与局部修改默认 inherit，不重新生图；只有新视觉体系、整体重做或我明确要求探索新方向时走 explore。已授权的范围内工作直接推进，真正改变批准计划时沿原重新对齐协议。仍须查看实际运行截图和验证相关交互，不修改托管 skill 或规则区。

正式采用 mancode 治理的新任务，先核对本地支持的入口；不要凭本包自动安装或升级。已有 TaskRef 继续原任务；没有活动/指定 TaskRef 且未选治理模式的普通工作保持默认 Solo，不为了视觉约定创建 session、任务或第二份账本。固定版本与兼容性边界见 [MANCODE.md](MANCODE.md)。

## 没有 mancode：独立使用

> 请按 SPEC.md 开展本次工作。先读现有页面、token、组件和真实资料，只确认仍会改变范围或方向的问题。已有设计体系默认沿用，在我已授权的范围内实现本次改动，不另起生图流程。若需要建立全新方向，先说明要决定什么，再选择合适的真实生图、可运行原型或设计规格。最后实际查看运行截图并操作受影响旅程，如实记录验证结果。

复用已有当前入口，确需新入口时才采用 [PROJECT.template.md](PROJECT.template.md)。不要求用户填写模板，也不为了本包另造文档体系。普通局部工作不需要完整的新审批材料。

## 八个文件各做什么

- [SKILL.md](SKILL.md)：入口，识别治理模式与视觉路由。
- [SPEC.md](SPEC.md)：阶段、视觉依据、变更与实际验收。
- [PROJECT.template.md](PROJECT.template.md)：通用项目的可选当前入口。
- [IMAGE-TO-UI.md](IMAGE-TO-UI.md)：inherit、explore、资产生成及实际截图的证据边界；保留文件名兼容引用。
- [EXAMPLE-media-review.md](EXAMPLE-media-review.md)：虚构审片例子，展示两种路由与旅程验证。
- [MANCODE.md](MANCODE.md)：原 TaskRef、最终执行确认与账本映射。
- [MODULE.template.md](MODULE.template.md)：单份受管模块计划，保留四个区块标记。
- 本文件：使用入口与日常提示。

## 在 Codex、DSH 或其他工具中使用

让助手读取文件夹即可，不要求安装才能使用。技能名称保持 develop-with-visual-spec；自动发现和安装目录由实际宿主决定，应核实后按授权接入。本 fork 没有验证宿主菜单发现，也没有向 Codex 或 DSH 安装全局文件。

不要把本 SKILL.md 覆盖到 mancode 生成的 man skill，也不要改托管区。长期接入只在已有授权内合并非托管引用，mancode 使用 [MANCODE.md](MANCODE.md) 的片段。通用模式可采用：

```markdown
本项目涉及 UI 的工作参考 ./develop-with-visual-spec/SPEC.md。
先读现有系统、实际页面和本次要求，确认 G2 视觉依据与变更边界。
已有体系默认 inherit，同体系接续、新页面/布局和局部修改不要求生图或重复图片批准。
新视觉体系、整体重做或明确的新方向请求才走 explore，按问题选择真实生图或原型。
资产生成单独处理，不改变周围 UI 系统。真实截图与相关交互验证在两种路由中都保留。
恢复时读取路由与有效依据，不把旧 G2 待办直接解释为必须生图。
```

复制到其他项目时重新核验路径，按授权接入。`mancode init` 不自动复制此目录。文档约束助手流程，不等于运行时会拦截提前实现或自动鉴别图片。

只有已选择生图的探索/资产工作依赖图像工具；不能生成时如实说明该部分阻塞，继续不依赖它的授权工作。真实原型可以是独立方法，但不能冒充生成图。用户明确选择了生图时，需要改变方法就说明并确认必要的替代决定；inherit 无需另办免生图批准。

## 日常继续、变更与局部工作

继续开发：

> 恢复当前路由、有效依据、用户要求与未完成工作；先核对实际文件和版本。已建立的设计系统继续沿用，完成后记录真实截图和相关交互结果。mancode 仍用原 CLI 与账本。

同体系扩展：

> 在现有设计系统中增加……页面。复用 token、组件和视觉语言，补充必要的局部布局规则，不重新探索整套风格；只问尚未决定的关键业务问题。

局部修改：

> 调整……的间距/字号/颜色，沿用现有方向，直接在已授权范围内修改并检查实际结果。不要为了这次改动先生成局部效果图。

改变方向：

> 这次希望重做……的视觉方向。先明确变化范围和需要选择的问题，给出可审阅方案，确认新方向后实施；不影响的区域继续沿用。

默认美学优先，未明确承诺的无障碍数值仅作末位诊断，不自动改变配色、增加装饰或重开 G2；语义、原生行为和项目明确承诺仍保留。验收分别看 VIS（视觉）、FLOW（旅程）、DATA（真实集成）、ENG（工程），任何一类通过都不自动证明另一类通过。
