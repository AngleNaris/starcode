# 从交互逻辑到图片，再到真实 UI

在 G1 放行后读取。图片是视觉决策依据，不是完整交互规格或可执行界面。mancode 模式的“当前入口”指绑定模块计划；G2 获批后先更新最终 plan baseline，再确认执行，图片批准本身不写成实现验证通过。

## 1. 准备生成输入

AI 从获批逻辑中提取：
- 画面任务、用户角色、当前页面与状态、主要/次要操作
- 信息优先级、导航结构、内容密度与真实长度范围
- 指定视口（宽 × 高、单位）与桌面/窄屏的优先级
- 共用视觉方向、现有品牌和可复用组件；确有授权的参考图片
- 固定样例编号：以后实现和截图复核都使用同一份样例

先看参考图片的像素，再提取可以执行的约束。长列表、长中文标题、长人名、空数据、很多版本等样例要有代表性；不以清一色短标题的漂亮样例掩盖真实布局问题。

### 可直接使用的提示词骨架

> 为以下已批准交互方案生成应用 UI 效果图。输出是可审阅的设计图片，不是代码。
> 逻辑修订与画面编号：由项目入口填写。
> 目标视口：由项目入口填写。
> 用户此刻要完成的任务：填写一个明确任务。
> 画面必须包含：按信息优先级列出区域、关键字段和操作。
> 当前状态与固定内容样例：引用样例，并写出必要内容。
> 视觉方向与共用组件：引用已批准参考，说明延续哪些规则。
> 布局限制：关键操作位置、最低可读尺寸、内容溢出处理。
> 不得改变：已批准的导航、业务状态与操作含义。
> 如文字不能精确呈现，保持布局占位，另以文案清单为准。

提示词必须具体到当前画面，不是“做一个高级感后台”。每轮保留提示词、使用的参考、工具名称、输出图片及其关联逻辑修订。只有实际输出并检查后，才能标为“已生成”。

## 2. 生成与批准

1. 确认环境具有真正的图像生成能力，按该工具要求调用。不要假定某个产品必有该功能。
2. 先生成关键屏，查看实际图片，检查逻辑覆盖、层级、阅读密度与操作可发现性。
3. 让用户选择或修订方向；获批后生成相关关键页面、窄屏重排和必要状态，沿用同一套规则。
4. 每张图保存稳定 ID 与修订。把待批准图片直接交给用户，标清范围与仍需解释的部分。

工具不可用或失败：提交一个可移交的生成任务包，内含本节输入、提示词、参考文件、输出视口和覆盖清单，G2 标为“阻塞”。用户提供外部生成图后，实际查看、核对并获得批准再继续。不要将任务包、图像链接占位或已有代码截图称为已生成效果图。

## 3. 用文字补足图片的边界

图像生成可能改写文字、丢失细小控件、让不同画面组件不一致；也不能精确表达焦点顺序、业务状态、响应式行为或每个像素值。因此，每组获批图旁保留简短补充：
- 文案：准确标签、错误信息、计量单位和格式；图片乱码不进入产品
- token：颜色、字体层级、间距、圆角、边框及主要布局尺寸；标注哪些是依据图片推导、哪些已获批
- 组件：按钮、输入框、导航、列表项等必要状态和复用规则
- 状态覆盖：每个必要状态对应具体图片，或对应已有批准组件＋文字行为规则
- 布局：目标视口、允许的滚动区域；长内容采用换行、截断还是展开；窄屏哪些重排/折叠
- 可访问性：语义元素、键盘可达、可见焦点、表单标签、读屏名称和对比度；目标标准如有需明确

不能机械复刻不可用设计。若可访问性或真实长文本要求影响批准布局，展示影响并重开相应视觉决策；可以保持外观的小语义修复无需重新设计。未展示的断点可以通过获批响应式规则实现；若出现全新信息架构，必须补图。

## 4. 分工明确的依据顺序

各类事实优先依据不同产物，不采用“一张图覆盖一切”的简单排序：
1. 用户最新明确批准的变更，覆盖其指定范围的旧批准内容。
2. 当前入口引用的获批逻辑与数据契约，决定行为、权限和数据含义。
3. 同一批准包中的精确文案、token、组件与响应式规则，决定图片难以准确表达的细节。
4. 当前入口引用的获批图片，决定指定状态/视口的视觉构图、层级与风格。
5. 既有代码和测试是实现证据；未批准草图、旧版本与模型猜测不能覆盖以上内容。

这些依据出现实质矛盾时停止相关部分，说明矛盾并确认修订；不能借助排序悄悄抹掉一项批准要求。精确规则补充图片，但不能以“文字优先”为由大幅改变图片结构。

## 5. 实现与截图检查

先提取共享 token 与组件，再实现关键屏并尽早截图。视觉不符时先修布局体系与共享组件，再调局部；避免页面间各自堆叠特殊值。

为每组参考图维护一份固定样例，至少保存：样例内容、角色与权限、页面/状态、目标视口、字体、主题与截图条件。生成图使用相同目标内容；实装截图使用同一数据样例和目标条件，不能一张用短标题、另一张用生产长标题后直接声称一致。工具输出分辨率与目标视口不同须记录比较方式，不假装像素一一对应。

检查顺序：信息和关键操作是否齐全 → 区域比例与对齐 → 字体与密度 → 组件状态 → 长内容/窄屏 → 键盘与可读性。关键屏可并排或叠图比对；整页长滚动场景还需检查截图以外的连续内容。

每条差异标记“应修复／已批准例外／生成噪声”，并给出依据。图像生成不适合保证严格像素一致；若项目确实要求像素级阈值，须先批准明确尺寸与容差，再使用适当测量。截图检查之后，另跑实际用户旅程；漂亮截图不证明播放、提交、保存或权限有效。
