# 模块计划模板：待填写模块名

## 目标与范围

- 用户目标、角色与本次可验收切片：待填写
- 交付等级（真实可用／受限试用／仅演示）：待确认
- 包含／不包含；现有架构、接口与复用依据：待填写
- 主要旅程（入口 → 操作 → 反馈 → 完成）：待填写
- 实体、关系、权限、状态、持久化与失败恢复：待填写
- 尚会改变范围/行为/验收/方向的未决项：待解决；没有时写“无”

## 实施所依据的设计基线

实施确认前必须用真实依据填写，不能用占位符放行：

- G1 逻辑修订、范围与原任务要求的批准记录：待填写
- G2 路由及理由：inherit／explore，待按实际选择
- inherit 依据：现有 token/组件、采用中的页面/实际截图、文件或稳定链接及版本，待填写；不需补办历史图片批准
- explore 依据（适用时）：所选生图/原型/规格、真实产物修订与引用、必要的方向决定，待填写
- 本次明确变更、未涉及的继承范围、已知缺陷与最新要求冲突的处理：待填写
- 精确文案、token、组件、目标窗口与长内容规则：引用实际定义
- 样例、角色、字体、主题与截图条件：待填写
- 独立资产需求及适用位置（如有）：待填写；不重置 UI 体系
- 所需新决定的可核对来源、明确标准承诺与接受的差异：待填写；没有则写“无”

已有体系内的接续、新页面/布局/状态和局部视觉修改可以沿 inherit，不触发强制生图或新的图片批准；原计划最终执行确认照常。默认审美优先，未明确承诺的无障碍阈值作末位诊断；保留语义与原生行为。

## 验收与证据设计

将条目同步进原 requirements；以下是文字模板，不是 CLI JSON。按真实需求保留/扩展，每项明确“给定 → 操作 → 结果”、数据模式、验收方法和实际观察面。验收 ID 与原 requirements 对齐，不制造重复条目。

- VIS-1：实际查看运行截图，对照本次所选视觉依据和变更要求；目标窗口、样例、关键结构与允许差异：待填写。方法/观察面：待确定。
- FLOW-1：实际走完相关旅程及必要失败/恢复路径：待填写。方法/观察面：待确定。
- DATA-1：真实读写、重新读取及相应身份/权限：待填写。方法/观察面：待确定；仅 mock 时明确限制，不标真实集成通过。
- ENG-1：适用构建、类型检查及相关测试：待填写。方法/观察面：待确定。

四类证据不能相互代替。纯后台无视觉影响时 VIS/G2 可不适用并说明；inherit 不免真实 UI 检查，G2 依据确认也不是 VIS 实现验证。非移动 GUI 不增加无关手机/平板矩阵；明确的 DPI/缩放等承诺仍保留。

- 阶段、依赖与每阶段的可验收结果：待填写
- implementation scope 对应的文件/目录、计划文档和必要资产：待填写并与实际 scope 一致
- 真实/模拟适配层、运行条件和限制：待填写，不记录密钥
