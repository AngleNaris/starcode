# 项目当前入口（通用模式模板）

仅适用于未使用 mancode 的项目。mancode 模式改用 [MANCODE.md](MANCODE.md) 和 [MODULE.template.md](MODULE.template.md)，不要复制本文件建立第二套任务/G3 状态。

使用方法：AI 在用户授权的项目位置复制并填写；默认可命名为 PROJECT.md，也可合并进现有入口。删掉不适用项。空白和“待确认”表示没有证据，不能当成批准或通过。图片、日志等只在实际产生后引用，避免空建目录。

## 当前摘要

- 项目／本次切片：待填写
- 用户目标与交付等级（真实可用／受限试用／仅演示）：待确认
- 本次包含／明确不包含：待填写
- 当前步骤与阻塞：待填写
- 代码版本或工作区状态：待填写
- 下一步：待填写

## 事实与决策

- 已证实事实及来源：待填写
- 低风险假设及依据：待填写
- 影响范围／数据／权限／关键旅程的待决项：待填写；没有则明确写“无”
- 本轮需要用户决定的少量问题与建议：待填写

## G1：交互逻辑

- 逻辑修订：待填写
- 角色、权限与主要使用场景：待填写
- 主要旅程（入口 → 操作 → 反馈 → 完成）：待填写
- 核心实体、关系、身份与持久化边界：待填写
- 数据来源／现有 API 适配与兼容问题：待填写
- 页面与关键状态：待填写
- 错误、取消、恢复与边界情况：待填写

验收条目，每项一小段即可：
- A1：给定……；当……；应当……。数据模式与验证方式：待填写。
- 其他确有必要的条目：由 AI 补齐。

## G2：视觉批准包

每张图片分别记录：
- 画面 ID／修订：待填写
- 实际图片文件或稳定链接：待生成
- 关联逻辑修订、验收 ID、页面和状态：待填写
- 目标视口、实际图片尺寸与固定样例 ID：待填写
- 生成工具、提示词及参考材料位置：待填写
- 已实际查看图片：否
- 未画出的状态及所沿用的批准组件／规则：待填写

本组共用补充：
- 精确文案：待填写或引用既有文件
- token 与组件：待填写或引用既有文件
- 窄屏／长内容／滚动／键盘与无障碍：待填写
- 未解决的视觉问题或拟接受的例外：待填写

## 放行记录

逐关记录，批准前保持待定：
- G1 状态：未开始。批准范围、产物修订、批准人、日期与可核对的批准消息/记录：待批准。
- G2 状态：未开始。批准图片及补充规则修订、范围、批准人、日期与依据：待批准。
- 实现状态：未开始。已完成／未完成：待填写。
- G3 状态：未开始。验收范围、证据与接受的限制：待验收。

## 实现与验证证据

- 模拟数据部分／真实数据部分：待填写
- 固定样例内容及位置、授权/脱敏情况：待填写
- 运行方法与所需配置（不记录密钥）：待填写

每次实际验证记录一项：
- 验证 ID 与关联验收 ID：待填写
- 类别（VIS 视觉／FLOW 旅程／DATA 数据集成／ENG 工程）：待填写
- 代码版本、环境、视口（如适用）、数据模式、样例：待填写
- 实际操作或命令、运行时间：未运行
- 结果（通过／失败／未运行／阻塞）与日志、截图或观察证据：未运行
- 未覆盖范围、已知限制、下一步：待填写

## 变更与接续

仅保留仍有意义的决定，长历史可引用其他文件：
- 变更 ID／原因／用户决定：待填写

- 尚未完成或等待谁的决定：待填写
- 接手者下一项具体动作与必读引用：待填写
