# 项目当前入口（通用模式模板）

仅适用于未使用 mancode 管理的项目。mancode 模式改用 [MANCODE.md](MANCODE.md) 和 [MODULE.template.md](MODULE.template.md)，不要复制本文件建立第二套任务/G3 状态。

AI 在用户授权的位置填写，或合并进现有入口；仅保留本次需要的部分，不为小改动强建整套文档。空白和“待确认”不能当成批准或通过。图片、日志等只在实际产生后引用，沿用既有系统无需“待生成图片”占位。

## 当前摘要

- 项目／本次切片及用户目标：待填写
- 本次授权、包含／不包含及交付范围：待填写
- 当前步骤、阻塞及下一步：待填写
- 代码版本或工作区状态：待填写
- 视觉路由（inherit 或 explore）与理由：待填写；已有体系默认 inherit
- 独立资产需求（如有）：待填写；不改变 UI 路由

## 事实与决策

- 已证实事实及实际来源：待填写
- 低风险假设及依据：待填写
- 尚会改变范围／数据／权限／旅程／视觉方向的决定：待填写；没有则写“无”
- 用户最新要求、本次变更与仍有效的既有决定：待填写

## G1：交互逻辑

引用已有有效要求，只补本次变化：

- 逻辑修订、角色、权限与场景：待填写
- 主要旅程（入口 → 操作 → 反馈 → 完成）：待填写
- 实体、关系、身份、持久化与 API 边界：待填写
- 本次相关页面／状态、失败与恢复：待填写
- 验收条目：给定……；当……；应当……。数据模式、验证方式及来源：待填写

## G2：视觉依据与变更确认

两种路由只保留适用部分，不把沿用事实写成历史批准：

### inherit：沿用体系

- 现有 token、组件与变体的文件及版本：待填写
- 采用中的相关页面、实际截图及观察条件：待填写；未查看时如实说明
- 本次沿用的排版、颜色、密度、布局与交互反馈：待填写或引用
- 本次明确改变的部分、复用方式、需补的局部规则：待填写
- 已知缺陷、过期来源或与最新要求的冲突及处理：待填写

同体系新页面/布局、状态和局部间距/字号调整可使用此路由，不要求生成图或新的图片批准。用户已有授权可以作为本次依据；不能编造此前的图片审批。

### explore：仅新方向工作

- 需要探索的问题与授权范围：待填写
- 所选方法（真实生图／真实原型／设计规格）及实际产物引用：待填写
- 产物修订、覆盖页面/状态/视口和固定样例：待填写
- 实际查看／运行检查与尚未解决的方向问题：待填写
- 必要的新方向决定及可核对来源：待填写；未决定时不能写为批准
- 仅选用生图时：真实工具、提示词、参考材料、实际输出位置/尺寸和检查记录。未生成时不得填“已生成”。

### 共用规则与确认依据

- 精确文案、token、组件、长内容与目标窗口规则：引用实际来源
- 本次美学目标与既有风格；明确承诺的标准（如有）：待填写
- 保留语义、原生键盘行为及项目反馈；无明确承诺的无障碍数值只作诊断，不单独重开 G2。
- 视觉依据充分性、本次授权与仍需确认的实质问题：待填写；不重复请求已有授权

## 实现与验证证据

- 模拟数据／真实数据边界：待填写
- 实际样例、授权/脱敏情况和运行方法（不记录密钥）：待填写

每次实际验证记录：

- 验证 ID、关联验收与类别（VIS／FLOW／DATA／ENG）：待填写
- 版本、环境、窗口/缩放（如适用）、数据模式及样例：待填写
- 实际操作或命令、运行时间与观察者：未运行
- 结果（通过／失败／未运行／阻塞）、日志/截图/观察证据：未运行
- 未覆盖范围、限制与下一步：待填写

VIS 要实际查看运行截图；FLOW 要实际操作相关旅程。两种路由均需检查，G2 依据确认和生成图片不等于实装通过。

## 变更与接续

- 新要求与实际授权、受影响逻辑/视觉依据/数据/组件：待填写
- 保持的路由与依据，或转入 explore 的具体原因：待填写
- 仍有效的决定、需重开的实质问题、实际批准来源（如有）：待填写
- 尚未完成的事项和下一项动作：待填写

恢复时先读取这些事实；旧模板的“G2 待办”不自动意味着必须生图。保留真实历史，不补造图片批准，不把现有缺陷固化为设计要求。
